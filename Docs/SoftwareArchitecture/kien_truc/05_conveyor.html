Control Box Protocol · Warning → Stop · Box Status Model

Tổng quan

Bất kỳ hộp đang dùng ở Warning → dừng băng tải; hết Warning → chạy lại. Một timer lo việc đó.

Luật

Mỗi khi một hộp đổi trạng thái, EnqueueControlBoxUpdate tính lại: có bất kỳ ô đang dùng nào ở Warning không? Kết quả (dừng / chạy) được đặt làm "mong muốn", và nhãn băng tải đổi màu (đỏ "Conveyor Stopped" / xanh "Conveyor Moving").

Một DispatcherTimer 200 ms (ConveyorTimer_Tick) so "mong muốn" với trạng thái đã gửi lần trước; chỉ khi khác mới gửi lệnh, nên không spam Control Box. Gửi hụt (không đủ echo) thì giữ nguyên "lần trước" để lần tick sau thử lại.

Gửi một trạng thái

AssertMotorChannels(on) đặt bốn kênh Motor 1..4 về cùng mức, lần lượt, cách nhau TX gap:

  • Mỗi kênh: AssertChannel gửi tới Retry lần (mặc định 4), cách nhau Retry gap (100 ms), dừng ngay khi có echo.
  • Mỗi lần gửi: SendChannel → SendTX ghi khung rồi chờ echo trong RX timeout (mặc định 500 ms), so từng byte.
  • Giữa hai kênh liên tiếp chờ TX gap (mặc định 500 ms).

Vì vậy thời gian phản ứng xấu nhất (hộp báo Warning → cả 4 kênh đã gửi) khi Control Box im lặng vào cỡ 4 × Retry × (RX timeout + Retry gap) + 3 × TX gap — hàng giây; khi Control Box đáp bình thường thì gần như chỉ còn 3 × TX gap.

Xung SWON lúc kết nối

Khi mở cổng Control Box (OpenControlBoxCore), app đưa Motor 1..4 về RUN (cách nhau TX gap) rồi phát một xung Start All: kênh 5 = HIGH, đợi 500 ms, = LOW. Toàn bộ chạy dưới khóa _controlBoxGate nên không đụng timer băng tải.

Lock / manual

Mở khóa bằng nút Lock (phải nhập mật khẩu) sẽ bật chế độ manual: timer băng tải ngừng tự điều khiển (_controlsUnlocked), người vận hành tự bấm các nút Start All / Stop 1..4 (group Motors), và sửa được các ô cài đặt. Khóa lại thì tự động hoạt động trở lại. Bản đồ hộp cũng chỉ cho kéo/đổi khi mở khóa (xem User Interface).
